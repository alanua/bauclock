# BauClock

BauClock is an open-source construction-site time-tracking and compliance-support system built around a FastAPI backend and Telegram bot.

It is designed for small construction teams that need reliable work-time records, site-scoped access control, pause/compliance checks, auditable corrections, and practical reporting without turning the application into a full payroll or HR suite.

## What BauClock covers

Current project scope includes:

- worker/site/company time tracking;
- Telegram-based worker interaction;
- FastAPI backend services;
- role- and tenant-scoped access control;
- manual time corrections with audit boundaries;
- pause-compliance support for German ArbZG workflows;
- calendar and request workflows;
- reporting/export foundations;
- PostgreSQL persistence with Alembic migrations;
- Redis-backed runtime support;
- regression tests for access-control and time-correction behavior.

BauClock supports compliance workflows; it does not provide legal advice or replace professional payroll/legal review.

## Architecture

```text
/bauclock
├── api/                 # FastAPI backend
├── bot/                 # aiogram 3.x Telegram bot
├── db/                  # shared database logic and SQLAlchemy models
├── access/              # access-control helpers/policies
├── docs/                # project and hardening documentation
├── tests/               # regression and service tests
├── docker-compose.yml   # local service stack
└── .github/workflows/   # CI
```

Core stack: Python, FastAPI, aiogram, SQLAlchemy, PostgreSQL, Redis, Alembic, pytest, Docker.

## Quick start

1. Clone the repository.
2. Copy the example environment file and provide local development values.

```bash
cp .env.example .env
```

3. Start the stack.

```bash
docker-compose up --build
```

Do not commit `.env` files, tokens, encryption keys, database credentials, or production data.

## Development environment

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt -r requirements-dev.txt
```

Start PostgreSQL and Redis for local development:

```bash
docker-compose up -d postgres redis
```

Run the test suite:

```bash
pytest
```

CI also runs the repository test workflow under `.github/workflows/tests.yml`.

## Database migrations

Alembic reads the application database URL from the same development environment as the app.

Apply migrations:

```bash
alembic -c db/alembic.ini upgrade head
```

Create a migration from model changes:

```bash
alembic -c db/alembic.ini revision --autogenerate -m "describe_change"
```

Always inspect autogenerated migrations before applying them.

## Security and access-control model

BauClock handles employment/time data and therefore treats tenant isolation, role boundaries, correction history, and secret handling as security-sensitive.

Access-control changes should include focused regression tests. Never use production personal data in public issues, pull requests, fixtures, or logs.

See [SECURITY.md](SECURITY.md).
